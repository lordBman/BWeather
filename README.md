# BWeather

A cross-platform weather app built with **bare React Native + TypeScript**, powered by the
free [Open-Meteo](https://open-meteo.com) forecast and geocoding APIs. No API key, no account,
no paid weather service.

> **This is bare React Native, not Expo.** Location and permissions use
> `@react-native-community/geolocation` and `react-native-permissions`; native `ios/` and
> `android/` projects are generated by the React Native CLI (see Setup below), not included
> pre-built, since those are machine-generated Xcode/Gradle projects rather than hand-written
> source.

## Project identity

| | |
|---|---|
| App name | BWeather |
| Bundle ID / Application ID | `com.bsoft.bweather` |
| Framework | React Native 0.74 (bare CLI, TypeScript) |
| Weather API | Open-Meteo `/v1/forecast` |
| Geocoding API | Open-Meteo Geocoding `/v1/search` |
| Icons | Iconify (`@iconify/react-native`) |
| State | Zustand (+ AsyncStorage persistence) |
| Navigation | React Navigation (bottom tabs + native stack) |

## Features implemented

- Current weather, hourly forecast, 7-day forecast, per-day detail screen
- Device location (with graceful fallback to manual search when denied)
- Worldwide city search via Open-Meteo geocoding, debounced
- Favorites with add/remove/reorder and duplicate prevention (stable coordinate-derived id)
- Celsius/Fahrenheit and km/h · mph · m/s unit switching
- Light / Dark / System theme
- Offline support: last-known-good forecast is cached per location+unit combo and shown with a
  "Showing last available data" banner when a live fetch fails
- Pull-to-refresh, loading skeletons, friendly error states (no raw API errors surfaced)
- Centralized WMO weather-code → description/icon/category mapping
- Top-level error boundary with a "Restart" recovery screen
- Accessibility labels on all interactive elements and key weather readouts

## Setup

### 1. Generate the native projects

This repo ships the app's TypeScript source, but not the generated `ios/`/`android/` native
projects (those are produced by the CLI, not hand-authored). Easiest path: scaffold a fresh RN
0.74 TypeScript app and copy this `src/`, `App.tsx`, and config files over it.

```bash
npx @react-native-community/cli init BWeather --version 0.74.5
# then copy this project's src/, App.tsx, package.json, babel.config.js,
# metro.config.js, tsconfig.json, .eslintrc.js, .prettierrc, app.json, __tests__/
# into the generated BWeather/ folder (overwrite the generated equivalents).
```

### 2. Set the bundle identifier / application ID

- **iOS**: open `ios/BWeather.xcworkspace` in Xcode → target **BWeather** → General →
  Bundle Identifier → `com.bsoft.bweather`. Add to `ios/BWeather/Info.plist`:
  ```xml
  <key>NSLocationWhenInUseUsageDescription</key>
  <string>Allow BWeather to use your location to show local weather and forecasts.</string>
  ```
- **Android**: in `android/app/build.gradle`, set `applicationId "com.bsoft.bweather"`. Add to
  `android/app/src/main/AndroidManifest.xml`:
  ```xml
  <uses-permission android:name="android.permission.INTERNET" />
  <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
  <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
  ```

### 3. Install dependencies

```bash
npm install
npx pod-install       # iOS only
```

### 4. Run

```bash
npm run android
npm run ios
```

### 5. Test / lint

```bash
npm test
npm run lint
```

## Testing

`__tests__/` covers the business logic the spec calls out explicitly:

- `openMeteo.test.ts` (19 tests) — URL building, response validation (including array-length
  mismatches), normalization, and every `getWeatherForecast` failure mode (network, timeout,
  rate limit, server error, malformed body) mapped to a typed `OpenMeteoApiError`
- `weatherCode.test.ts` — WMO code → description/icon/category mapping, including the unknown-code
  fallback and day/night icon selection
- `temperature.test.ts` — rounding (no decimals shown) and unit-aware formatting
- `dateTime.test.ts` — location-local (not device-local) timestamp formatting, same-hour
  detection, today/tomorrow labeling, and sunrise/sunset progress clamping
- `favorites.test.ts` — add/remove/reorder and duplicate-favorite prevention by stable id

All of the above were additionally sanity-checked by executing the underlying logic directly
with `tsx` (no test framework) during development, since this sandbox has no network access to
install `jest`/`ts-jest`/`zustand` — every check passed. Once you run `npm install` in a real
environment, `npm test` runs the same suites with Jest directly.

## Known limitations / next steps

- Native `ios/`/`android/` folders must be generated locally (see Setup) — they aren't meaningful
  to hand-write and weren't included as inert placeholder files.
- Reverse-geocoding a raw GPS fix into a friendly place name is stubbed as "Current Location"
  (`useLocation.ts`) since Open-Meteo's geocoding API is forward (name → coordinates) only; wiring
  up a reverse-geocoding provider is a natural next step.
- Component/snapshot tests for screens aren't included yet — the business-logic layer (api,
  utils, stores) has full coverage per the spec's "at minimum" requirement.
